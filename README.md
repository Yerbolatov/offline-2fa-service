# offline-2fa-service

Самостоятельно разворачиваемый веб-сервис локальной двухфакторной
аутентификации для изолированных (air-gapped) корпоративных сетей.
Дипломный проект студента SE-2401.

## Проблема

Облачные MFA-сервисы, SMS и push-уведомления требуют внешних каналов связи.
Их нельзя использовать в закрытых сетях государственных, банковских,
промышленных, оборонных и исследовательских организаций. Поэтому такие
организации могут быть вынуждены полагаться только на пароль, который
подвержен фишингу, повторному использованию и краже учётных данных.

Проект решает эту проблему с помощью локального сервиса, который работает
внутри корпоративной сети и не зависит от интернета или сторонних облачных
провайдеров. Предполагается наличие внутреннего NTP-сервера и внутреннего
удостоверяющего центра (CA).

## Целевые пользователи

- **Системные администраторы и специалисты по информационной безопасности** —
  развёртывают сервис, управляют пользователями и контролируют аудит.
- **Сотрудники организации** — проходят аутентификацию с использованием
  пароля и второго фактора.
- **Разработчики внутренних приложений** — подключают приложения через REST
  API или endpoint forward-auth.

## Цель и ожидаемые результаты

Цель проекта — спроектировать и реализовать простой самостоятельно
разворачиваемый сервис двухфакторной аутентификации, пригодный для
полностью изолированной корпоративной сети.

Ожидаемые результаты:

- работающий локальный сервис с аутентификацией по паролю и TOTP;
- подключение TOTP через QR-код и резервные коды восстановления;
- административная панель с RBAC и журналом аудита;
- REST API и интеграция с reverse proxy через forward-auth;
- безопасное хранение секретов и защита от перебора и повторного использования
  кодов;
- развёртывание с HTTPS и внутренним CA без внешних CDN и сервисов;
- автоматические тесты, спецификация API и документация по эксплуатации.

## Объём проекта

### Входит в MVP

Сервис предоставляет локальную аутентификацию по логину, паролю и TOTP без
доступа к интернету, SMS, push-уведомлениям и облачным MFA-провайдерам.
Предполагаемая инфраструктура закрытой сети включает внутренние NTP и CA.

- вход по логину и паролю;
- подключение TOTP через QR-код;
- проверка одноразового кода и защита от повторного использования;
- резервные коды восстановления;
- роли пользователя и администратора;
- журнал аудита;
- REST API и endpoint forward-auth;
- HTTPS с сертификатами внутреннего удостоверяющего центра;
- автономное развёртывание без внешних CDN и сервисов.

### Дополнительные направления

WebAuthn/FIDO2, OIDC, LDAP/Active Directory, RADIUS и экспорт журналов в SIEM
рассматриваются как направления дальнейшего развития и не являются
обязательной частью текущего MVP.

В проект не входят SMS, e-mail и push-уведомления через внешние сервисы,
биометрия и отдельное мобильное приложение.

## Выбранные технологии

- **Backend:** Python и FastAPI;
- **хранилище MVP:** SQLite;
- **интеграция:** REST API и forward-auth для reverse proxy;
- **второй фактор MVP:** TOTP по RFC 6238;
- **хеширование паролей:** Argon2id;
- **шифрование TOTP-секретов:** AES-256-GCM с отдельным ключом;
- **развёртывание:** автономная установка в изолированной сети;
- **диаграммы:** draw.io.
